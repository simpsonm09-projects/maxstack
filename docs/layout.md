# Layout

- `AGENTS.md` sets working rules for changes to this repository.
- `layers.json` is the ordered layer manifest. Each layer is described once: its `name` (the plugin id), its `kind`, its `source`, and a `runtimes` map. The `pstack` layer's source is a git pin into the fork. The org and personal layers are local checkouts with a `path` and a git URL. A layer lists the runtimes it installs for: `claude`, `opencode`, and `copilot`.
- A layer can declare `workspaceInstructions` in `layer.json`. The installer composes selected declarations into workspace `AGENTS.md` and, when Claude is selected, `CLAUDE.md`. A root collision uses `.maxstack/workspace-instructions.md`.
- `t3.gatedInstances` and `t3.readOnlyInstances` in workspace settings generate `.pstack/pstack-t3-instances.json`. The lists are per-machine, and the installer records ownership in `stack.lock.json`.
- `scripts/generate-layers.mjs` and `scripts/lib/` project layer skills and OpenCode MCP into a dedicated output directory. `docs/neutral-layer-generator.md` defines the contract.
- `.github/workflows/ci.yml` calls the shared `repo-standard` checks, runs the manifest validation in `test`, and runs the fast Node tests in `test-node`. The installer fixture lifecycle runs under Bun on Linux in `portable.yml`. `mise.toml` pins the linters.
- `justfile` is the local task runner; its recipes mirror the CI checks.
- `pstack.lock.json` is the one pin for the pstack plugin: the fork, the `path` inside it, the commit, and the branch it came from. `scripts/verify-manifests.py --online` checks that the branch still points at the commit.
- `workspace/opencode.jsonc` is the workspace config base: default agent, permissions, and the MCP startup timeout. It sets no model. Layer fragments supply the MCP servers, and the installer names each nested OpenCode entry in the `plugin` list.
- `docs/mcp.md` defines the workspace MCP servers and their default states. `docs/mcp-installation-guide-v2.md` is the original source guide.
- `docs/plugin-publishing.md` describes how the installer assembles each runtime and records it in `stack.lock.json`, and how CI validates it.
- `docs/t3-setup.md` is the T3 setup: OpenCode needs nothing extra, Claude Code needs a provider instance whose launch arguments pass `--plugin-dir` to the generated `.claude/plugins` folder, Copilot needs a provider instance that starts the generated `copilot.sh`, and Pi needs a provider instance that starts the generated `pi.sh`.
- `docs/relationship.md` names how `maxstack`, the plugin layers, and `dev-setup` fit together, and defines the workspace by behavior.
- `scripts/install/layer-sources.ts` holds the layer-source rules: the `-Source` specs, how each layer's source resolves, the source record in the lock, and the `-Update` report.
- `scripts/install/discovery.ts` holds the target rules: the order of `-Workspace`, `MAXSTACK_WORKSPACE`, the cwd marker walk, and the installer layout, the path refusals, and the origin the installer prints first. It refuses when none identifies a workspace. `scripts/Install-WorkspaceDiscovery.test.mjs` tests those rules.
- `scripts/Install-Workspace.*.test.mjs` are the installer tests, split by topic: `settings`, `selection`, `removal`, `status`, `runtimes`, `sources`, and `instructions`. They share fixtures and helpers from `scripts/lib/installer-test-kit.mjs`, which exports them and holds no test. The `portable` workflow runs the installer suite under Bun with `just test-linux`; the full suite is `just test-node`.
- `scripts/install/workspace.ts` reads `layers.json` and, for each layer, builds the runtimes it lists: the Claude plugin folders in `.claude/plugins`, the OpenCode plugin folders in `.opencode/plugins` with their agent profiles in `.opencode/agents`, the Copilot and Pi wrappers in `.maxstack/bin`, and the Pi settings in `.pi/agent`. It composes selected `workspaceInstructions` declarations into `AGENTS.md`, `CLAUDE.md`, or `.maxstack/workspace-instructions.md`, writes the gated instance list under `.pstack` when configured, merges config fragments into `opencode.jsonc`, and records the outputs in `stack.lock.json`.
- `workspace/maxstack.settings.json` is the path-free seed of the optional workspace settings file. The installer reads the file at the workspace root, which the user owns: it never writes or owns it. `docs/features/settings.md` describes it.
- `schemas/maxstack.settings.schema.json` is the JSON schema for that file. `scripts/verify_settings.py` checks the schema, the seed, and the reader against `scripts/install/settings.ts`.
- `scripts/check-agent-tools.mjs` checks that the agent tool set in the retired `dev-setup` archive covers the service owners the org integration registry names. It is workspace-local and reads the sibling checkouts, so CI does not run it.
- `scripts/verify-workspace-skill.sh` runs a bounded OpenCode session that loads a skill. `scripts/verify-workspace-install.py` checks the generated Claude, OpenCode, Copilot, and Pi files against `stack.lock.json`.
- `docs/decisions.tsv` is the append-only decision trail. `docs/setup-plan.md` is the historical setup plan.
